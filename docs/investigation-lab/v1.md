# Investigation Lab V1 — local review

The release is local and unpublished. It preserves the homepage opening and existing backgrounds, tools, project cases, Learning Studio and its storage. No repository visibility or provider settings were changed.

## Connected experience

- `/engineering/lab`: a four-case investigation workspace, linked from the homepage, Engineering Studio, public case reading guides and private-source design illustration.
- Three historical public captures: checkout replay, claim redelivery and SettlementLab's independent collateral target. A fourth authored toy-contract exercise exposes no private source or runs.
- Each case supports a prediction, individual record reveals, provenance, authored review, a falsifiable challenge, correction comparison, notes, completion and resume.
- Weekly challenge: a transparent four-case rotation, changing Monday UTC; it does not claim new weekly content or live activity.
- Ask a project: a narrow public-context assistant. The selected curated records are inspectable before asking; there is no live repository or web retrieval.
- Requirements Critic: a local deterministic ambiguity/acceptance/boundary checklist with optional AI review.
- Trade-off Explorer: explicit goal and options, a comparison-planning checklist and optional AI analysis of benefits, assumptions, failure modes and next experiments. No performance or cost measurements are invented.
- Every report distinguishes observed/supplied information, interpretation, missing evidence, next checks and what would change the answer.
- Personal notebook: local report saves, editable notes, investigation resume, completion counts, Markdown report download/copy and JSON notebook export. Up to 100 saved reports. Progress counts are on-device only, not analytics or verified skill scores.

## Evidence and AI boundaries

Guided explanations are authored, planning checklists are rule based, and generated answers are explicitly AI interpretations. No service, model, code, proposed fix or benchmark is executed merely by opening a case. The correction comparison checks reasoning against an authored guide, not a newly executed implementation.

`POST /api/investigation` accepts allowlisted case/evidence IDs or bounded planning inputs. Context is built server-side. Private notes, saved reports, user-supplied source URLs and arbitrary client evidence are excluded. A 16 KB body cap, the existing origin/rate-limit guard, server-only credentials, provider timeout/cancellation and bounded structured response validation are enforced. Unknown reference IDs and malformed answers fail closed, without an invented AI fallback. Valid structure and IDs do not establish semantic correctness.

The endpoint uses the existing Cloudflare credentials and shared limiter, with model `@cf/meta/llama-3.3-70b-instruct-fp8-fast` and JSON schema mode. No keys are added or copied to the client. Only an explicit Ask AI action sends the displayed question and public/typed context to the provider. Questions and personal text are not logged by this route.

- https://developers.cloudflare.com/workers-ai/models/llama-3.3-70b-instruct-fp8-fast/

Local preview adapts only a loopback request URL to its actual loopback Host on the same port because Next dev normalizes 127.0.0.1 to localhost. The shared origin/rate-limit guard is unchanged. Non-loopback, different-port and malformed hosts cannot use this adapter; it is enabled only for `DAI_LOCAL_PREVIEW=1`.

## Saved-state integrity

Storage key: `eai-investigation-notebook-v1`. There are no reads or writes to existing study/recruiter keys. Version/shape validation rejects damaged or unsupported data before writing. Expected-byte checks prevent a stale tab from silently overwriting another tab's work. On corruption, quota errors or concurrent updates, the original disk copy is protected and current work remains exportable in memory. Notebook JSON is an export format; an import/restore UI is not part of V1.

## Verification limits

Behavioral tests cover provenance alignment, partial evidence, foreign/duplicate IDs, weekly boundaries, notebook round trips, corruption, concurrent writes, failed storage, requirements/trade-off rules, provider schema/citations, bounded body parsing, cancellation and real route integration with mocked guards/provider. Mocked provider responses are synthetic tests, not a live-model evaluation. Local browser review exercises the genuine unavailable-provider path; no paid live-model run is claimed.
