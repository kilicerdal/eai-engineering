# Choose a project to review

These projects share quality-engineering principles, but demonstrate different system boundaries. All business examples use synthetic data.

| Project | Main question | Strongest proof | What it does not claim |
|---|---|---|---|
| [AI Agent Reliability Lab](https://github.com/kilicerdal/agent-reliability-lab) | Does an agent choose the right cause, cite supporting evidence, and respect operator approval? | [Recorded handoff comparison](https://kilicerdal.github.io/agent-reliability-lab/#evidence-handoff), blind incident benchmarks, and [approval replay](https://kilicerdal.github.io/agent-reliability-lab/#approval) | Production incident performance or independent authorship of the current cohorts |
| [Playwright AI Automation](https://github.com/kilicerdal/playwright-ai-automation) | Does the browser/API assertion detect a wrong commerce outcome? | Healthy control, missing-restock fault and source mutation survivor-to-detected example | Live autonomous AI, real payment processing, exhaustive mutation coverage |
| [SettlementLab](https://github.com/kilicerdal/settlementlab) | Can matching, approval, shared balances and replay remain correct? | Balanced settlement recovery and independent collateral replay defect | Real market connectivity, official exchange calendar, production identity |
| [Healthcare Quality Platform](https://github.com/kilicerdal/ai-healthcare-quality-platform) | What happens when a claim commits but queue acknowledgement fails? | PostgreSQL identity preservation across simulated SQS redelivery and changed-content conflict | Real AWS reliability/IAM certification, patient records or exactly-once infrastructure |
| [Healthcare Quality Lab](https://github.com/kilicerdal/healthcare-quality-lab) | Can an independent reference challenge generated expectations and payment state? | Rejected wrong oracle, reviewed expectations, concurrency and interruption recovery | General model accuracy, payer operations or healthcare compliance |
| [eAI Engineering](https://github.com/kilicerdal/eai-engineering) | Can a reviewer inspect these decisions through a coherent public experience? | Public case-study tour, dated source records and website browser checks | Running every reference system when a story is opened |

For agent evaluation, citation support, and human approval controls, begin with Reliability Lab. For a browser-automation role, begin with Playwright. For transaction correctness, begin with SettlementLab. For service/data integration, begin with Healthcare Platform. For test-oracle and AI-evaluation discussion, begin with Healthcare Lab. Use the website as the presentation layer, then follow the source evidence to the relevant repository.
