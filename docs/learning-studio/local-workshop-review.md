## Storage and boundaries

New isolated key: `eai-practice-workshop-v1`. Explicit Save workshop draft stores the selected activity and its writing; reload resumes the chosen activity at Choose. Each activity retains its own goal, selected answer, response and takeaway draft. Keep creates a separate immutable snapshot (up to 100, no eviction). Simulation controls reset when leaving Try, as stated beside the retry experiment. They are not recorded proof of completion.

Download exports current writing including unsaved drafts. Restore merges matching drafts and append-only takeaways. Differing drafts, conflicting snapshot identities, invalid fields, unsupported versions and excess capacity stop the operation without replacing the original. Cross-tab changes block saving until the user downloads/reloads. Unsaved writing contributes to the shared status, warns on browser unload and blocks ordinary internal link navigation until saved/downloaded. Browser history navigation is not a durable save; use Save before leaving.

No AI calls, services, payments or arbitrary code are executed by these activities. The retry exercise imports the same authored sequential example as the existing public walkthrough. Existing production evidence remains dated and pinned; this is not a rerun of repository integration tests.
